# Status (2026-11-13)

## Where things stand
Version 0.3.2, released 2026-11-13. Works: dot and separator in the menu bar, the bar below the menu bar listing hidden items, pressing one opens its real menu, Accessibility only, ~0% CPU idle.

New in this session (0.3.2, unreleased): **the parked-inline leak is fixed.** macOS 27 draws parked items inline next to short app menus (e.g. Herdr) while Accessibility reports them parked behind its chevron — the squeeze's own check read "0 hidden icons drawn" and never fired, so iStat Menus Disks/Sensors/Teams sat visibly next to the app menu for good. The spacer now covers the whole gap from the end of the frontmost app's menus (its `AXMenuBar`) to the separator — stable across macOS's async re-packs — and a settle check 2 s after every squeeze catches the late re-pack (the dance used to end before macOS settled, with icons drawn that nobody re-pushed). Design and evidence: [findings.md](findings.md#the-parked-inline-leak-measured-live-2026-11-13-external-display-2048x858-pt-herdr-in-front), behaviour: [KB.md](KB.md#hiding-pushing). Verified live on the external display: the dance converges to a clean bar within ~1 s of an app switch, idle CPU 0.0%.

**Seated opening (0.3.1-era, verified):** clicking (left *or* right) a below-bar icon that is not drawn seats it just right of the separator for the moment of the press, so its menu opens next to the separator where it is visible on any display, and the item returns to its hidden order when the interaction ends. Right-click asks the item for its context menu (`AXShowMenu`). Freshly seated items are pressed with a real synthetic click at their drawn position (BetterDisplay and Apple's agent items ignore the accessibility press there). Design and evidence: [findings.md](findings.md#seating-a-clicked-item-next-to-the-separator-2026-11-11), behaviour: [KB.md](KB.md#opening-an-item).

**Published (0.3.0):** the app is now distributed like the siblings — `scripts/make-dmg.sh` builds a Developer ID-signed, notarized and stapled DMG attached to each GitHub Release; an app icon is generated at build time (`scripts/make-icon.swift`); *About dotbar* opens the standard About panel from the dot's right-click menu; MIT `LICENSE`; install instructions in the README. The operator's own install keeps the local `dotbar local signing` certificate so its Accessibility grant stays intact; switching it to the Developer ID identity needs a one-time re-grant (KB §Signing).

Docs (2026-11-12, docs-only push): the README now shows screenshots like the sibling repos — the bar below the menu bar in light and dark, and a clicked item's real menu opening at the seat (`docs/`). Taken from the agent session itself: Screen Recording turned out to be available to the session host, and the bar responds to real synthetic CGEvent clicks but not AX presses (measured: [findings.md](findings.md#screenshots-and-real-clicks-from-an-agent-session-measured-2026-11-12)).

## Hard constraint (settled by research 2026-11-05)
No tool can open another app's menu or popover under dotbar's bar: the app anchors it to its own icon's position in the real menu bar, and the icon must be drawn there when pressed. Thaw 3 and Bartender live with the same limit. The design choice is therefore *where* the clicked icon is drawn for that moment — the seat answers it: next to the separator, briefly. Evidence: [findings.md](findings.md#why-the-other-menu-bar-managers-broke-on-macos-27-read-2026-11-05).

## Known limits
- An icon macOS drops before dotbar ever saw it in this run cannot be pressed; it shows dimmed (if remembered) until there is room once — except single-item-app ghosts, which the seat now makes clickable.
- On the laptop dotbar's own separator is dropped too (it sits leftmost), so the hand-picked hidden list only takes effect while there is room.
- A packed laptop bar may displace the leftmost visible icon into the chevron while a seat is open; it comes back on restore.
- The spacer's menus-end anchor is untested on the laptop screen alone: the notch's inline drawing zone starts at the notch's left edge, not at the menus end, so the anchor may under-cover there (see [findings.md](findings.md#the-parked-inline-leak-measured-live-2026-11-13-external-display-2048x858-pt-herdr-in-front)).
